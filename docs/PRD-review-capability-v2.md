# AI PR Review V2：能力目标与边界

更新：2026-10-16。本 PRD 定义要达到的用户能力，不把计划当作已实现功能。实施顺序、当前状态和验收方法唯一见[Review V2 执行计划](review-v2-development.md)；当前快照见[交接入口](../HANDOFF.md)。

## 产品目标

做一款轻便、可检查、可控成本的 PR 审查工具：从冻结的 PR 变更出发，发现真实问题、按需查看相关跨文件证据、说明不确定性，并让用户看见每条候选如何被确认、扣下或因覆盖不足而未完成。AI 帮助人工审查，不取代人工，也不把 PR 描述当作项目规范。

能力目标：Agent 负责提出和修订审查假设；轻便指本地优先、有限依赖和按需恢复；好用要求报告清楚覆盖、证据与状态；便宜要求质量不降时减少实际调用/usage/重复工作；可靠要求输入身份、阶段结果、取消、失败和发布可追溯；自进化只允许知识候选在隔离回放和人工确认后晋升。

## 用户可见结果

一次审查应给出：

- 审查快照身份（repo、base SHA、head SHA、规则/提示/知识版本和可用模型信息）。
- 每条候选的变更、预期/实际行为、原始文件行证据、关系/入口依据、反证，以及判定链。
- 已检查范围、每个 hunk 状态、因预算/工具错误/取消/未知而跳过的内容。覆盖不完整时明确标 `partial`；不能把“无已发布发现”显示为“没有问题”。
- 最终路由：发布、待人工确认、被判据扣下或未验证；重复运行有可理解的稳定身份。
- 成本/用量只显示实际收集值，区分逻辑 token、供应商缓存 token、已知费用与未知 usage。

## 判定原则

Bug 候选需解释变化如何从可达入口影响可观察行为，并绑定 frozen source 引文。静态 import、同名方法、路径相似或模型置信度都只是证据线索，不单独证明运行时关系。有限 witness 只能证明受限表达式在给定输入域内存在/未发现差异，不证明完整程序契约或入口可达。缺少入口/契约/反证时保留 `needs_context/partial`，不伪装为 confirmed 或 dismissed。

工具诊断和模型判断分开：Ruff 可确定报告一条 lint 诊断，但是否由 PR 新增、是否导致用户可观察 bug 是不同问题。`confidence` 是组件输出字段，除非通过独立校准，不解释成正确概率。

知识条目必须有 source repo/SHA/file:line、适用范围、反例/失效边界、版本和来源 case；用户接受/拒绝是标注线索，不直接成为 gold。candidate 与 authoritative 隔离；自动自改生产规则、自动提示词优化和 RSI 不在当前交付范围。

## 架构边界

第一版仍用当前 Python/TypeScript、本地优先和既有 CLI/GitHub Actions/Web；每个入口都必须如实显示未实现能力和 partial 状态。PR 工作保持独立分支/草稿审阅，不自动合并 main。真实模型实验先核预算上限、冻结协议与回滚方式；不把评测 gold/答案注入待评审 prompt。**VS Code 插件被冻结，当前不是受支持入口或交付目标**；保留代码/安全检查不代表支持承诺。

数据处理顺序：冻结变更快照 → 有界静态信号/检索 → Agent 假设与跨文件计划 → 宿主限额读取原始证据 → 候选核验 → 带覆盖账本的结果 → 核对 PR 当前 head 后发布。阶段结果绑定 repo/base/head、审查器/策略/模型配置与输入哈希；模型不得改写 source identity、伪造引用、扩大预算或隐去遗漏。工具不可用、超时、取消和结果未知都需可观察，发布不能覆盖旧快照为当前结果。未知远端调用结果不自动无限重试，已发生费用不可撤回，不承诺 exactly-once。

存储先单机文件：不可变阶段产物、原子 checkpoint、任务身份、锁和显式 resume。仅在实际出现事务并发/跨主机调度或文件能力经测量不足时评估 SQLite/其他存储；默认不引入 Redis、MQ、PostgreSQL 或微服务。队列只能解决分发/恢复，不能证明质量或降低单次推理费用。

## 非目标

- 不承诺完整全仓调用图、所有语言语义分析、任意代码执行/测试沙箱、必然找到所有 Bug 或零误报。
- 不以固定 hunk/token 限额假装完整审查；低预算要显式 partial。
- 不将测试数、synthetic fixture、位置匹配、选择器覆盖、缓存命中率或规则命中数包装成语义质量和真实 token 节省。
- 不因“Agent”名义迁移大框架，不默认增加数据库、消息队列、向量库或独立服务。
- 不将 VS Code 插件列入当前里程碑，不删源码或相关安全检查作为本轮收敛手段。

## 验收基准

按执行计划的三阶段验收：可信主链的失败/partial/恢复反例；跨文件审查的冻结 PR 人工语义 N/S/D/P；失败案例知识的隔离回放、人工晋升和独立留出。每个比例必须公布分子、分母、样本、评测协议、模型/配置/知识版本和未知费用。质量与成本必须同案同范围比较；少审不能算省钱。开发集用于迭代；被接触过的 holdout 不再称独立留出。
