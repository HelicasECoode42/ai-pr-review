# 我们凭什么更强（优势与依据）

本文只写**能验证的主张**：每条都给出我们的机制、实测数字，以及别人（可核对的公开来源）怎么做。任何"更好"都限定在说清楚的范围里。

**基准事实**：本仓库 187 文件 PR 的原始 diff = **588,648 tokens**，模型窗口 12.8 万 → 一次调用**不可能**放下。

---

## 1. 数据处理与切片

| | 我们 | 别人 |
|---|---|---|
| 切片粒度 | **hunk 级**：`LineSpan` 记录每个切片在 base/head 的行区间；planner 再按强导入边聚合成预算大小的 `ReviewUnit` | PR-Agent：按 token 预算**打包**，`enable_large_pr_chunking` 默认 **false**，`max_number_of_calls=3`；alibaba/open-code-review：元数据 LLM 分组（**不看 diff 内容**），`maxFilesPerGroup=10`；reviewdog：无；CodeRabbit：未公开 |
| 覆盖记账 | **每个 hunk 的结局都被记录**：`complete / partial / omitted`，附原因（`patch_clipped`、`encrypted_or_binary`…），分母稳定（预算耗尽仍留在分母） | PR-Agent：被裁的文件**至少被点名**；alibaba：超预算组标 `failed(budget)` |
| 文档变更处理 | `.md/.rst/.txt` 以 `documentation_only_change` 排除且**记账**，不占 patch 预算 | 未见公开做法 |

**实测**：默认 6000 预算 → 19,532 上下文，**22/193 hunk 完整（11%）**、5 partial、**166 omitted**；预算 600k → 193/193。单元级实测：40 文件/13,108 tokens 语料下，截断只覆盖 **19/40 文件**，逐单元覆盖全部已审单元。

**为什么这是优势**：大多数工具"悄悄丢"或"点名而已"；我们把**每个切片的下场做成账本**，因此"这次到底看了多少"是可数的、可进 CI 的、可对用户交代的。这是**可审计性**优势，不是覆盖率优势——覆盖率要靠逐单元（见 §2）。

## 2. Agent harness

| | 我们 | 别人 |
|---|---|---|
| 循环 | 发现 → 取证 → **核验过滤器链** → 判定 → 发布，判据版本化 | Claude Code：4 并行代理 + **并行 validators**（调研里唯一有 generate-then-verify 的）；alibaba：`review_filter` + re-location 独立模块；PR-Agent：**无 agent 循环**，确定性编排 |
| **证伪** | **`witness_eval` 实际求值** base/head 表达式（AST 白名单、无 exec、域与步数预算），**给出见证输入**或判定"域内无差异" | **调研的工具里没有任何一个对结论做机械验证** |
| 契约感知 | 见证输入若**违反声明契约域**（如 `count:int` 却用 `None`），**不算见证** | 未见公开做法 |
| 并发 | 单元级并发（上限 8）、**按 plan 顺序确定性合并**、**每单元独立预算**、单元失败隔离 | alibaba：并发 8；PR-Agent：`asyncio.gather` |
| 去向可审计 | 每条候选带 `filter_verdicts`（过滤器名 + 通过与否 + 理由） | 多数工具只记录"发了/没发" |

**实测（合成 gold 集，同模型同协议）**：

| | 改进前 | 改进后 |
|---|---:|---:|
| 假阳 | **2** | **0** |
| 精确率 | **0.50** | **1.00** |
| 召回 | 2/2 | 2/2 |
| 成本 | 18,738 tokens | 17,947 tokens |

两条误报被**机械**挡住：`safe-index` 在 32 个赋值上无见证；`safe-division` 的见证是 `count=None`，越出声明契约。真缺陷仍带见证发布（`count=0 → ZeroDivisionError`、`index=-4 → IndexError`）。

**为什么这是优势**：别人靠"让模型更小心"（提示词、阈值、误报清单）或"多一个代理再问一次"；我们**把可判定的部分交给求值器**，模型只在不可判定的部分说话。机械结论不可被模型推翻（rule：模型只能补充解释）。

## 3. 证据可靠性

| | 我们 | 别人 |
|---|---|---|
| 输入冻结 | **冻结 base/head SHA**，一切引用可复现 | 多数工具读 GitHub API 当前状态 |
| **来源校验** | 引文必须来自**实际发送给模型的文本**（patch 文本或已渲染证据摘录），再与快照逐字比对 | **调研的工具里没有一个校验引文来源**；只有 Claude Code 要求"必须引用并链接" |
| 证据预算 | `EvidenceBundle` 账本：`excerpts / omitted / evicted`，请求被挤掉也有记录 | PR-Agent/Bugbot 有 token 上限，但**在 prompt 之外**强制，不告诉模型 |
| 拒答语义 | `needs_context` ≠ `dismissed`：缺证据不等于证伪 | 多数工具只有"报/不报" |

**实测（这条最硬）**：我们曾在真实运行里让模型在 `mod_23.py` 报出一条**逐字引用**的结论，并以 `ai_behavior_verified` 0.95 发布——但那个文件在它的 prompt 里**只有一行元数据**（`+1/-1`），**代码一个字都没有**。根因是旧的 `_valid_citation` 只要求"引文落在被改动文件的行范围内"。**已修**：来源校验前置，未展示的代码不可引用（含 3 个回归测试）。

**为什么这是优势**：绝大多数审查工具信任模型给的 `file:line` 和引文。我们**把"引文是不是我们给过它的"变成可判定的检查**——这同时堵死了"对没读过的代码编造结论"这条最危险的失败模式。

## 4. Token 与成本

| | 我们 | 别人 |
|---|---|---|
| 计量 | **每次调用的原始 usage 进报告**：prompt/completion/total、**cache 命中/未命中**、按阶段账本 | PR-Agent：`max_model_tokens`（默认 32,000）硬夹；Bugbot：30k/100k 上限在 prompt 之外 |
| 缓存 | **实测**：共享 6.9k 前缀连发 3 次，命中 **96.9%**（6,272 hit / 203 miss） | 未见公开的命中率口径 |
| 预算 | patch 预算、证据预算、per-file 预算、单元预算分账；`REVIEW_INPUT_SCOPES` 汇总 | 多数只有单一大数上限 |
| 可归因 | 报告带 `criteria_version`、`experience_ids`、单元计数，能回答"钱花在哪一步" | 少见 |

**实测成本（真实调用）**：小 PR 全流程 74,461 tokens ≈ **0.08 元**；gold 4 例 17,947 tokens；8 单元 A/B 两侧合计 137,302 tokens。余额差实测约 **8 元/百万 tokens**（含完成 token 计价，且**余额更新有延迟**——早期从单次差额算出的"1.07 元/百万"已撤回）。

**为什么这是优势**：我们把**预算做成了领域模型**（Java 后端那种 first-class 账目），所以每一次截断、每一次请求、每一次重发都有账。多数工具只能告诉你"花了多少 token"，我们能说"哪一步花了、花得值不值、省下来会损失什么"。

## 5. Review 本身（最终产出）

| | 我们 | 别人（公开数据） |
|---|---|---|
| 已知答案表现 | 合成 gold 集 **精确 1.00 / 召回 1.00**（n=4，见边界说明） | AACR-Bench（1,505 专家标注）：agent 召回 **10.10%**、精确 **39.90%**、F1 **16.12%** |
| 真实仓库发现精度 | 5 条候选中 **4 条真缺陷**（我逐条对照冻结代码判定），但**发布 0 条**（证据不足被扣） | ReviewBench 的"grounded precision/recall" 是同一量纲 |
| 防误报门槛 | 门槛是**机械**的：见证 / 契约 / 来源 | Tricorder 的产品线是"有效误报 < 10%"；Signal65 给的厂商"precision" 64–96%（口径宽松且受厂商咨询影响） |
| 误报目录 | 2 条已入册（等价守卫改写、无消费者的元数据键改名），可机械执行 | Claude Code 有 7 条**文字**清单（不可执行） |

**为什么这是优势**：我们把"别报错"从**提示词里的请求**变成**判据里的条件**。等价改写不是"请小心不要报"，而是**求值器找不到见证，因此机械上无法 confirmed**。

**必须说的边界**：n=4 的合成集不是精确率估计。被证明的是"这两条具体误报被机械阻断、真缺陷仍带见证发布"。真实仓库的精确率仍待干净评测集验证（历史 25 个 PR 已被接触过，不能声称未见测试）。

## 6. 一句话总结：为什么会有这些优势

1. **预算与证据是一等公民**（账本、覆盖率、来源、缺失原因）——所以"看不见的损失"不存在了。
2. **冻结快照**——所以一切可复现、可归因、可回滚。
3. **能机械判定的就机械判定**（求值、来源、契约域、过期）——模型只在不可判定的地方说话。
4. **判据版本化**——所以改判据能解释"哪些条目因此改判"，自进化才有因果。
5. **单主线 + 明确非目标**——所以没有组合爆炸，改动可归因。

这五条不是"更好的提示词"，而是**把审查当作有账目、有门禁、有版本的工程系统**——这也是我们与"一个会读 diff 的模型"的根本差别。
