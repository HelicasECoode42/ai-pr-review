# GitHub publication lifecycle

GitHub Actions publishes summaries and inline comments only from a report whose repository, pull request, and head SHA match the current run. The publication gate also requires a successful or degraded execution, an allowed report confidence, a candidate-ledger run ID that matches the lifecycle inventory, and unique candidate IDs and suggestion mappings. An inline suggestion additionally needs an exact mapping to a `ready_for_publication` candidate and an approved source label. These checks keep legacy or incomplete reports out of the publishing path.

The inline publisher writes `publication.json` into the run's report directory. Its top-level status describes what the workflow could establish: `complete` means all candidates reached recorded outcomes; `partial` means an API outcome is uncertain or publication stopped before every candidate was attempted; `stale_head` means the PR changed before publication; `unavailable` means the report or publication identity failed validation. A rejected report records `withheld_report_not_eligible` per suggestion, so artifact readers can distinguish a closed gate from an attempted publication.

Candidate outcomes retain duplicate and author-dismissal decisions. The reusable workflow recognizes its own fingerprint marker to report `already_published`, and a PR author's `/ai-review dismiss` reply to a marked comment produces `dismissed_by_pr_author`. These are completed outcomes and do not create another comment. A `ready_for_publication` ledger state means the reviewer verified and mapped a candidate; it does not mean GitHub accepted a comment.
