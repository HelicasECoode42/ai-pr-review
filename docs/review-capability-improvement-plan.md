# 审查能力提升方案（2026-10-13）

这是研究结论与下一轮实验设计，不是已实现功能或效果承诺。

## 本项目已经观察到的瓶颈

冻结的 25 个 ReviewBench 任务最终保留 12 条建议，报告 hidden_suggestions_count 合计 58，Evidence Gate rejection 记录 1 条，14 个任务上下文截断。隐藏计数是汇总口径，不能把 58 条都当成真问题，也不能把 gate 记录再机械相加。需要逐条保留原始候选和各阶段拒绝理由才能归因。

现有 prompt 要求 uncertain 的置信度低于 0.65，而评测过滤阈值为 0.65：这些候选可能在获得更多上下文、经过 Critic 之前就消失。置信度是模型自报值，并非校准概率。当前 filter 把不同原因汇总为 hidden，缺少原始候选审计。

现有 prompt 和 Evidence Gate 要求引用新增行，排除删除行和未改动行。合理的评论定位要求不应限制缺陷证据只能来自新增行。删除验证逻辑、调用方使用错误、跨文件契约不一致都应允许引用 base/head 多位置证据，同时独立计算评论锚点。当前 Evidence Gate 只验证摘录和场景字段存在，不证明行为成立。

当前评测没有完整仓库工具检索；新增 Critic Python 导入依赖读取只是局部能力，不是对调用方、接口、配置和测试的完整分析。已有实验不能归因所有漏报都来自截断。

## 原始资料与可借鉴内容

1. [Claude Code Review 官方文档](https://code.claude.com/docs/en/code-review)：在完整代码库背景下按问题类型发现候选，再按实际代码行为验证。可以借鉴发现/验证分离、项目 REVIEW.md 和不同问题视角；文档不是本项目收益证据。
2. [PR-Agent 开源上下文处理](https://github.com/The-PR-Agent/pr-agent/blob/main/pr_agent/algo/pr_processing.py)：扩展 patch 周边上下文，区分 base/head 内容与预算遗漏。借鉴完整函数窗口和覆盖清单。
3. [PR-Agent self-reflection](https://github.com/The-PR-Agent/pr-agent/blob/main/docs/docs/core-abilities/self_reflection.md)：候选后续评分、排序、过滤。这是实现先例，不能据此认为我们的 Critic 有效；本项目原 Critic 对照是负收益。
4. [ContextBench](https://arxiv.org/abs/2602.05892)：作者报告复杂 agent scaffolding 在上下文检索上的收益有限，已探索与真正利用的上下文存在差距。该结果来自 coding agents，不能直接当作审查实验；启发是记录实际检索/使用证据，而非只加架构。
5. [GitHub ReviewBench 官方介绍](https://github.blog/ai-and-ml/reviewbench-an-open-benchmark-for-ai-code-review/)：类别/严重程度评测、grounded/augmented 区分；GitHub 报告独立多模型 ensemble 的一次实验在自身线上系统改善指标。它支持探索独立候选发现，不支持把其增益数字迁移到我们。
6. [Code Review Agent Benchmark / c-CRAB](https://arxiv.org/abs/2603.23448)：通过人类 review 构造对应测试并保留独立测试质量门槛。启发是加入外部预期/测试，不只是让模型投票。

## 实施顺序

### P0：记录候选流失，分开发现与发布

为每个候选赋 ID，保存原始输出、归一化位置、证据、failure scenario、每次处理决定及理由。区分 parse failure、低自报置信度、定位失败、去重、数量上限、证据摘录缺失、Critic dismissed/uncertain。先保留待验证候选，再用证据确定发布；不把宽松生成直接变成宽松发布。

离线复核 58 个隐藏候选（如果旧日志没有原文，明确无法恢复并重跑固定开发样本）。输出各阶段 TP 留存和 FP 留存、原始候选召回与最终报告召回。首先检查是没发现，还是发现后删掉。

### P1：固定仓库快照，按变更行为检索

每个变更符号包含完整函数、必要类定义、base/head 差异。按具体问题获取调用方、被调用实现、类型/schema、错误处理、配置和已有测试。提供只读 search/read/find_references 工具，设轮数/文件数/总 token 预算；模型必须说明缺少什么信息后再检索。统一给 Reviewer 和 Critic 证据包，避免后者读得更少。

每个任务保留未覆盖符号、读取的 SHA、文件/范围、截断及引用清单。不能只扩大一个大 prompt，也不能只收集 import 前两个文件。

### P2：以行为证据验证，支持多位置与删除证据

Finding 结构包含触发条件、调用路径、预期行为、实际行为、反例、PR 引入关系及 base/head 引用。评论锚点与证明位置分开。Critic dismissed 必须有明确反证；缺上下文先获取，仍不足则 pending，不计入确认问题。可执行的候选在隔离环境运行最小复现；优先同一输入 base 正常/head 失败，再用独立预期检查。依赖缺失、测试写错、旧版本已错不是已验证新 Bug。没有测试的逻辑问题也可由充分代码契约确认，不能强制每条都可运行。

### P3：增加审查视角，用具体后果审查设计

先作为有固定总预算的多个审查 pass，不假定需要新 Agent 架构：正确性/边界、接口契约/跨文件、状态/安全、封装/维护性。每个视角从代码独立发现，不先看到规则结论或其他 pass 的结论。合并根因后共享验证。

浅封装：定位重复透传、调用者必须了解内部实现、没有稳定约束的接口，而不是见到薄 wrapper 就报告。
接口错乱：参数/返回值/异常/异步语义是否在实现与调用者之间不一致。
函数不到位：缺失的分支、失败传播、清理操作或输入范围，并列触发样例。
高耦合：跨层私有依赖、循环依赖或扩散修改，并列受影响调用点。没有具体后果的个人设计偏好单列建议，不作为正确性 Bug 计分。

规则扫描可以提供另一个独立候选通道，但不能作为主审事实。确凿的类型/编译错误保留诊断出处；正则风险命中仍要证明可达性和后果。

### P4：控制实验判断模型还是流程瓶颈

采用 2×2：同一 DeepSeek 模型/另一个可用模型 × 当前上下文/按行为检索上下文。固定输入、reviewer commit、judge、生成与验证预算；按同一组案例成对比较。第一轮关闭 Critic 过滤；另行比较同模型二次验证、独立模型验证、行为验证，保存过滤前后集合。

当前 25 个公开样本已经被用于研究，只能作开发回归。新增按仓库分组的未见测试集，禁止用其标签指导检索或 prompt。黄金标签只能在执行后诊断时读取。

报告 grounded recall、augmented precision、各类别/严重程度指标、每 PR 误报、候选/最终召回、过滤掉的 TP/FP、上下文覆盖、调用数、完整 token/成本和延迟。重复运行检查随机性；保留建议集合做逐条独立标注。新增有效问题由独立裁定认可，不靠扩大报告数量制造提升。

## 当前结论

优先做 P0 与 P1，可以定位和修复已观察到的问题；P2 让可信度来自证据；P3 才能覆盖用户关心的契约和设计；P4 决定是否更换模型或使用 ensemble。GEPA/RSI 暂不启动。没有测得更高的真实问题覆盖、可接受的误报与成本之前，不宣称审查能力已经提高。

## 已实现的第一轮实验版本

新增 GitSnapshot/GitHubSnapshot 固定 base/head 的只读证据接口，EvidenceBundle 提供定义窗口、旧版代码、符号引用/调用方和显式遗漏。Python 定义使用 AST；其他语言是标明截断的源代码窗口，尚未实现跨语言完整语义调用图。GitHub 后端最多搜索40个候选文件/读取60个对象，局部搜索会报告不完整，不能把本地 git grep 评测结果等同于远端穷尽检索。

发现最多三轮，支持 read/search；行为验证最多两轮，要求触发、调用路径、预期、实际和 PR 引入原因。成立与否仍由模型进行 source reasoning，程序只校验引用真实存在、结构完整、反证出处和状态；不声称数学证明，也没有自动执行目标仓库测试。候选、处理原因、证据范围和请求均留档，低发现置信度不再提前过滤。验证缺证据或失败进入 pending。

CLI、Web 和 Agent 的默认 one-shot 路径接入，ENABLE_REPOSITORY_REVIEW 可关闭。显式 two_stage 仍使用原有模式。新增 ReviewBench paired 命令生成新控制组与新版组，固定提交/模型/源码预算/单次输出与超时；新版调用更多，必须报告总开销。旧约4%试跑只作历史参考。

### 格式试跑后的修正

最初三个配对任务发现了 DSML 包装请求数组和 JSON 字符串直接换行的问题。新增受限格式适配，仅接受 read/search 数据，不执行工具标签中的任何命令，不补全截断 JSON；适配会留档。明确的补查请求可替换低价值初始窗口，审查范围与替换记录保留。TS/Java等大括号语言新增显式标记为 heuristic 的定义范围；不是跨语言语义解析。

成立判定采用来源校验、完整因果解释及 verifier 的 confirmed 决定，不把模型自报浮点置信度当作校准概率再次删掉已确认候选。原始置信度保持不变，自动 GitHub 行内发布仍有高置信度门槛，未确认候选不会被发布。此策略可能提高误报，必须通过独立判分测量，不能凭结构完整就宣称行为一定正确。新实验同时判分最终报告与原始候选，检验确认流程到底带来什么。

### 明确推理强度与预算失败

89943fe 的高强度工程试跑发生输出预算耗尽，并且至少一个任务返回的 JSON 只损坏了末尾容器闭合。该试跑已停止，已完成/失败/中断记录保留在 reports/evaluation/paired-89943fe，进行中的用量不可得，不伪装成完整总花费。正式下一轮显式设置 reasoning_effort=low，两组同条件，不能与高强度试跑或旧4%合并计算。DeepSeek 文档说明默认 high、思考模式忽略 temperature；参见 https://api-docs.deepseek.com/guides/thinking_mode/ 。

兼容处理只纠正完整响应中的错误闭合容器类型，保留全部键值和字符串，不补 EOF 的未闭合容器，不合并多个 JSON 对象。读取请求缺 tool 但明确给出 path 时按只读请求解释；缺 line 的重复请求继续读取已给范围之后的窗口，而非重复返回文件前缀。所有推断/修正均记录，不能据此认定模型的行为判断正确。检索仅访问固定 git 对象中的源码路径，避免为搜索拉取媒体和 vendored 产物。
